# Brief → 7 拍 → 文案与字幕

## 1. 先拆一句话

把用户原话拆成六个槽位。缺的用默认值，不要追问超过一次。

| 槽位 | 要问自己 | 缺失默认 |
|---|---|---|
| 主体 | 这是谁/什么产品/什么作品？ | 用用户原句里的名词 |
| 承诺 | 看完观众得到什么？ | “把一件事说清楚” |
| 受众 | 给客户、同事、评委还是社媒？ | 客户/泛观众 |
| 调性 | 克制、温暖、锋利、科技、复古？ | 克制编辑感 |
| 行动 | 看完做什么？ | 不加 CTA，用片名收束 |
| 规格 | 时长、画幅、语言、交付格式？ | 60s / 16:9 / 中文 / MP4 |

例：

> “帮我做个 30 秒视频，介绍我们新出的手冲咖啡，叫北岸，感觉要安静一点。”

拆解：主体=北岸手冲；承诺=安静、讲究的日常；受众=咖啡爱好者；调性=安静/纸感/暖；行动=记住品牌；规格=30s 横屏。可直接开工，不需要再问。

调性定下来后立刻映射到主题：安静/纸感 → `quiet` 或 `letterpress`；理性/现代 → `swiss`；电影/夜 → `cinema`；技术/系统 → `tech`。主题选择表见 `styles.md`。

## 2. 七拍结构

所有片子都用同一副骨架，只改每拍的时长与内容。

| # | 拍 | 作用 | 60s 占比 | 30s | 15s |
|---|---|---|---|---|---|
| 1 | 钩子 | 片名/主张，定气质 | 0–3s | 0–1.5s | 0–1s |
| 2 | 问题/语境 | 为什么需要 | 3–10s | 1.5–5s | 1–2.5s |
| 3 | 转折/系统 | 核心做法或结构 | 10–21.5s | 5–11s | 2.5–5.5s |
| 4 | 细节证明 | 精度、参数、真实感 | 21.5–33s | 11–17s | 5.5–8s |
| 5 | 能力/规模 | 覆盖、速度、库存 | 33–44.5s | 17–23s | 8–10.5s |
| 6 | 结果/行动 | 交付、CTA、结果 | 44.5–55s | 23–28s | 10.5–13.5s |
| 7 | 收束 | 片名回落、slogan | 55–60s | 28–30s | 13.5–15s |

表内时间都是 **60s 基准**；`config.duration` 改后运行时自动等比缩放，30s/15s 列是折叠参考。15 秒版不要硬塞七拍：合并 2+3、4+5，保留钩子、核心、收束。90 秒版把 3/5 各加一拍，不改变顺序。

每一拍只回答一个问题：

1. 这是什么气质？
2. 没有它会怎样？
3. 它怎么运作？
4. 凭什么信？
5. 能做到多大/多快？
6. 最后得到什么？
7. 记住哪句话？

## 4. 文案写法

### 标题

- 4–8 个汉字；两行时每行 3–5 字。
- 动词优先：“各归其位”“起止之间”“随手可取”。
- 不写形容词堆叠，不写完整口号；口号留给片尾 slogan。
- 同一支片里标题句式保持一致（都短句，或都名词短语）。

### 副题

- 12–24 字，回答“所以呢”。
- 例：“拉一条曲线，画面前后就连起来了。”——具体动作 + 结果。
- 避免“赋能/引领/革新/一站式”这类空词。

### 微标签

- 页眉：`品牌 / BRAND` + 英文副标；右上 `01 — 素材 · FOOTAGE`。
- 标签只做信息层级，不承担叙事；全大写、加字距、字号小。
- 时间码、参数、编号可以“假精确”（`00:04:12`），但要在全片保持一致。

### 片尾

- 主片名 + 一句 slogan + `© 2026 BRAND`。
- slogan 6–14 字，和片头主张呼应，不引入新信息。

## 5. 字幕（烧录）

字幕写在 `js/script.js` 的 `subtitles` 数组，用**场景内定位**（60s 基准）：

```js
{ scene: 's1', at: 0.4, dur: 1.8, text: '一句话，先要有画面' }
```

- `scene`：字幕归属的场景 id，必须存在。
- `at`：场景内开始秒数；`dur`：持续秒数。都在 60s 基准下书写，运行时随片长自动缩放。
- 跨切点的 `at + dur` 会被 `timeline.js` 自动夹回该场景内，并打警告；写的时候就别跨。
- 旧写法 `{ start: 3, end: 4.8, text }` 仍兼容，但新工程不要用：改场景起止或片长时它会错位。

规则：

- 每条 8–16 字；超过 16 字拆成两条。
- 60s 基准下每条 1.8–2.4 秒；最短不低于 1.2 秒；阅读速度 ≤ 约 7 字/秒。
- 不在场景切点跨条：切点前 0.2 秒内结束，切点后 0.1 秒再起。
- 一条字幕只表达一个动作或判断，句末不加句号。
- 字幕是“解说”，不是标题复读：标题给判断，字幕给过程。
- 片头 2–3 秒只留片名，不急着上字幕；最后一条在结束前 2–4 秒收住。
- 缩短片长时先减条数，不要把所有字幕压成 1 秒以内：30s 片 ≤ 12 条，15s 片 ≤ 7 条。
- 字幕由 `js/subtitle.js` 与 `timeline.js` 统一挂载；场景里不要自己画字幕，也不要改字幕颜色。

检查方法：`npm run check` 查顺序、重叠、越界、单条时长、阅读速度与跨切点；`npm run qa:layout` 量字幕是否压字/出框；`npm run qa:timing` 核对“该出现时出现、不该出现时没有”；`npm run qa` 抽帧看实际观感。字幕位置与主题样式在 `styles/base.css` + `styles/themes/*.css`。

## 6. 三种常见 brief 的拍法

### 产品宣传（30–60s）

钩子=产品名 + 一句气质；语境=使用场景的痛点；系统=产品如何解决（3 步）；细节=材质/参数/工艺；规模=系列/库存/渠道；结果=使用后的状态；收束=品牌 + CTA。画面用产品特写、材质对比、使用动作，不用伪 NLE。

### 功能/软件讲解（60–90s）

钩子=一句主张；语境=旧方法的混乱；系统=界面/流程（伪 UI 最有效）；细节=一次关键操作；规模=能力清单/数据；结果=导出/交付；收束=片名。每个功能只给一个镜头，不要在一个画面里塞三个卖点。

### 活动/品牌开场（15–30s）

钩子=活动名 + 日期；语境=一句主题；系统=三个关键词；细节=地点/嘉宾/规模；结果=时间地点；收束=Logo + slogan。少讲故事，多给信息；字幕承担 80% 信息量。

## 7. 把模板术语换成本行业术语

模板里的伪 UI、素材库、导出单都是“剪辑软件”语境。换主题时，必须整组替换，不能只改页眉。参考映射：

| 模板原词 | 咖啡 | 软件 | 活动 | 护肤 |
|---|---|---|---|---|
| 素材 | 豆单 / 产地 | 数据源 | 嘉宾 | 成分 |
| 时间线 | 冲煮流程 | 工作流 | 日程 | 护理步骤 |
| 字幕 | 风味笔记 | 提示文本 | 串场词 | 使用说明 |
| 关键帧 | 注水节点 | 版本节点 | 彩排节点 | 吸收节点 |
| 素材库 | 豆仓 | 组件库 | 物料库 | 配方库 |
| 导出 | 出杯 | 发布 | 开场 | 上脸 |
| 付印单 | 冲煮单 | 发布单 | 执行单 | 配方单 |
| 262 件 | 12 支豆 | 128 个组件 | 36 位嘉宾 | 24 个 SKU |

同时替换（全部在 `js/script.js` 对应场景节里改）：

- S2 顶部文件名 `城市清晨 / 01_城市清晨_v07.film` → 你的项目名/版本号。
- S2 轨道上的片段名（巷口空镜、早餐摊的热气…）→ 你的流程节点或场景名。
- S5 的 8 个素材卡名称与时长 → 你的产品/环节/嘉宾。
- S6 的六张回顾卡（素材/时间线/字幕/关键帧/素材库/导出）→ 与本片七拍一致的关键词。
- S4 的曲线标签（缩放/位移/不透明度）→ 行业参数（水温/粉量/时间；帧率/码率/时长）。

做不到整组替换时，换场景，不要保留“别人的界面”。

## 8. 交稿前自检

- [ ] 七拍齐全，每拍一个问题，没有两拍说同一件事。
- [ ] 每拍都有屏幕文案，字幕与标题不重复。
- [ ] 片名在片头、片尾各出现一次；slogan 只在片尾。
- [ ] 所有数字/日期/品牌名一致（不要一处 2026、一处 2025）。
- [ ] 字幕不跨切点；60s 基准下最短 1.2s、最长 2.4s，阅读速度 ≤ 约 7 字/秒。
- [ ] 字幕全部用 `{scene,at,dur}` 场景内定位，没有残留旧 `{start,end}`。
- [ ] 调性与主题一致（安静 → `quiet`/`letterpress`；理性 → `swiss`；技术 → `tech`）。
- [ ] 没有空词、没有中英混排抢主视觉。
- [ ] 读一遍总时长：按每秒 4–5 个汉字估算，字幕总字数与时长匹配。
- [ ] 缩短片长后已减条数，没有把单条压到 1 秒以内。
