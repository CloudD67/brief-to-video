# Brief → 故事 → 分镜 → 文案与字幕

## 0. 先立规矩

**本文只服务宣传片（promo）。** MV 不拆“卖点七拍”，它按 `mv-craft.md` §0 写故事弧、人物关系、歌词段与镜头候选；两套语法不要混。

宣传片和 MV 一样，**每支片现场写**。模板只提供舞台、主题、组件、引擎与 QA；故事、拍数、场景、画面都由这一支片的 brief 决定。

- 先写故事，再写分镜，再写文案，最后才是版式与画面。
- 拍数由故事决定，不是固定七拍；七拍只是“卖点型” brief 的一种可选节奏。
- 判断标准：把品牌名换成另一个同类品牌，如果故事仍然完全成立，说明写得太通用，重写。
- 参考片只借技术（动效、转场、真实卡片），不借皮肤（配色、吉祥物、字标、CTA、镜序）——否则还是换名模板。产品片的完整拆法见 `product-film-grammar.md`。

**动手拆拍之前，先按 `brief-expansion.md` 把一句话扩写成 treatment。** 本文负责“怎么把已经足够丰富的故事拆成拍”；扩写负责“故事里到底有几个世界、几个空间、多少条候选镜头、几个色域”。跳过扩写，后面的七拍/分镜只是把一句空洞的话排得更整齐。硬件/实体产品尤其先读 `hardware-promo-grammar.md`。

## 1. 先拆一句话

把用户原话拆成六个交付槽位。缺的用默认值，不要追问超过一次。

| 槽位 | 要问自己 | 缺失默认 |
|---|---|---|
| 主体 | 这是谁 / 什么产品 / 什么作品？ | 用用户原句里的名词 |
| 承诺 | 看完观众得到什么？ | “把一件事说清楚” |
| 受众 | 给客户、同事、评委还是社媒？ | 客户 / 泛观众 |
| 调性 | 克制、温暖、锋利、科技、复古？ | 克制编辑感 |
| 行动 | 看完做什么？ | 不加 CTA，用片名收束 |
| 规格 | 时长、画幅、语言、交付格式？ | 60s / 16:9 / 中文 / MP4 |

再补四个**故事槽位**。这四个槽位才决定这支片长什么样：

| 槽位 | 要问自己 | 缺失默认 |
|---|---|---|
| 主角 | 这支片里是谁在经历一件事？可以是一个人、一件物品、一个地方、一条线 | 从主体里挑一个具体对象，不要用“用户 / 大家 / 我们” |
| 欲望 | 他想要什么？ | 把承诺翻译成一个具体动作或结果 |
| 阻力 | 什么挡着他？ | 时间、距离、失败、看不见的规则 |
| 改变 | 最后他和开头有什么不同？ | 问题被看见、被解决，或得到一个新视角 |

例：

> “帮我做个 30 秒视频，介绍我们新出的手冲咖啡，叫北岸，感觉要安静一点。”

拆解：主体=北岸手冲；承诺=安静、讲究的日常；受众=咖啡爱好者；调性=安静/纸感/暖；行动=记住品牌；规格=30s 横屏。故事槽位：主角=清晨独自开店的咖啡师；欲望=在第一位客人来之前把手冲调准；阻力=只有一小时的晨光；改变=第一杯递出去，窗外刚好亮起来。

调性定下来后映射到主题：安静/纸感 → `quiet` 或 `letterpress`；理性/现代 → `swiss`；电影/夜 → `cinema`；技术/系统 → `tech`。主题选择表见 `styles.md`。

## 2. 写一个能直接拍的微型故事

不设字数：写到人物、动作、阻力与改变都能落到画面为止。动工前先用中文写出来，给用户看一眼。模板：

> **主角** 在 **时间/地点** 里，想要 **一个具体的东西**，但 **阻力** 挡着他。他试了 **动作**，最后 **改变**。

例（咖啡）：

> 天还没亮，咖啡师拉开卷帘门。今天的第一位客人还有一小时才来，他想把手冲的水温、粉量和时间都调准。他一遍遍称豆、注水、倒掉，直到第三杯才点头。门铃响时，他把杯子推过去，窗外刚好亮起来。

例（DeepSeek 概念片，三种不同主角）：

> - 终端里的检索者：在空白的命令行里反复提问，想把“不知道”变成一个能用的答案；最后问题被折叠成一条路径，交到下一个提问的人手里。
> - 档案馆里的记录员：抽屉里全是没解出来的问题；他顺着一条蓝线走，错了上千次，最后把折叠图交给一个孩子。
> - 一条蓝线：从窗口出发，穿过纸页、雨和星座，把散落的答案串成鲸鱼的形状。

产品/功能只是故事里的道具或结果，不要写成卖点清单。

## 3. 故事 → 拍

把故事拆成 5–8 拍。每一拍必须**推进故事的一环**（主角—欲望—阻力—改变），不是“一个卖点一个镜头”。

| 片长 | 拍数 | 每拍时长 |
|---|---|---|
| 60s | 5–8 拍 | 6–14s |
| 30s | 4–6 拍 | 4–8s |
| 15s | 3–4 拍 | 3–5s |

每一拍只回答一个问题：

1. 谁，在什么地方，想要什么？
2. 什么挡着他？
3. 他做了什么？
4. 结果怎样？
5. 最后他变成了什么样？

拍与拍之间要有“因此 / 但是”的关系：上一拍的结果导致下一拍，或上一拍的努力被下一拍否定。只是并列的画面，不叫分镜。

## 4. 分镜表模板

动工前先填完这张表。每一行都必须有“这一拍发生什么”和“屏幕文案”，空着就说明这拍没想清楚。

| 时间 | 场景 id | 这一拍发生什么 | 屏幕文案（主/副） | 画面 | 转场 |
|---|---|---|---|---|---|
| 0–4 | s0 | 天没亮，卷帘门被拉起 | 北岸 / 把清晨烘进一杯里 | 街灯、门脸、纸感大字 | 硬切 |
| 4–13 | s1 | 他称豆、注水，第一杯倒掉 | 先调准水，再谈风味 / 92°C · 1:15 | 豆盘与手部特写，水汽 | 硬切 |
| 13–23 | s2 | 第二杯还是不对，他停了一下 | 有些早晨，要重来三次 | 台面、电子秤、窗外的蓝 | 硬切 |
| 23–34 | s3 | 第三杯成了，他点头 | 第三杯，才像今天 | 杯口、光、手 | 硬切 |
| 34–48 | s4 | 门铃响，第一位客人进来 | 客人不问，只喝了一口 | 门、逆光、杯子推过台面 | 硬切 |
| 48–60 | s5 | 窗外亮起来，他继续下一杯 | 北岸 / 把清晨烘进一杯里 | 店内外同框，片名回落 | 硬切 |

表里的秒数是 60s 基准；30s/15s 按比例压缩，或直接按第 3 节的拍数重写。场景 id 与数量由你自己定，不要求 `s0`–`s6`，也不要求七个。

## 5. 七拍只是可选节奏

下面这张表适合**卖点型 brief**（功能发布、产品迭代、能力清单）。它是参考，不是骨架；故事型、人物型、概念型片子不要硬套。

| # | 拍 | 作用 | 60s 占比 |
|---|---|---|---|
| 1 | 钩子 | 片名/主张，定气质 | 0–3s |
| 2 | 问题/语境 | 为什么需要 | 3–10s |
| 3 | 转折/系统 | 核心做法或结构 | 10–21.5s |
| 4 | 细节证明 | 精度、参数、真实感 | 21.5–33s |
| 5 | 能力/规模 | 覆盖、速度、库存 | 33–44.5s |
| 6 | 结果/行动 | 交付、CTA、结果 | 44.5–55s |
| 7 | 收束 | 片名回落、slogan | 55–60s |

15 秒版不要硬塞七拍：合并 2+3、4+5，保留钩子、核心、收束。90 秒版把 3/5 各加一拍，不改变顺序。用不用七拍，看 brief 更像“故事”还是更像“清单”。

## 6. 文案写法

### 标题

- 4–8 个汉字；两行时每行 3–5 字。
- 动词优先：“各归其位”“起止之间”“随手可取”。
- 不写形容词堆叠，不写完整口号；口号留给片尾 slogan。
- 同一支片里标题句式保持一致（都短句，或都名词短语）。

### 副题

- 12–24 字，回答“所以呢”。
- 例：“拉一条曲线，画面前后就连起来了。”——具体动作 + 结果。
- 避免“赋能/引领/革新/一站式”这类空词。

### 微标签

- 页眉：`品牌 / BRAND` + 英文副标；右上可用编号与小标签。
- 标签只做信息层级，不承担叙事；全大写、加字距、字号小。
- 时间码、参数、编号可以“假精确”（`00:04:12`），但要在全片保持一致。

### 片尾

- 主片名 + 一句 slogan + `© 2026 BRAND`。
- slogan 6–14 字，和片头主张呼应，不引入新信息。

## 7. 字幕（烧录）

字幕写在 `js/script.js` 的 `subtitles` 数组，用**场景内定位**（60s 基准）：

```js
{ scene: 's1', at: 0.4, dur: 1.8, text: '一句话，先要有画面' }
```

- `scene`：字幕归属的场景 id，必须存在。
- `at`：场景内开始秒数；`dur`：持续秒数。都在 60s 基准下书写，运行时随片长自动缩放。
- 跨切点的 `at + dur` 会被 `timeline.js` 自动夹回该场景内，并打警告；写的时候就别跨。
- 旧写法 `{ start: 3, end: 4.8, text }` 仍兼容，但新工程不要用：改场景起止或片长时它会错位。

规则：

- 每条 8–16 字；超过 16 字拆成两条。
- 60s 基准下每条 1.8–2.4 秒；最短不低于 1.2 秒；阅读速度 ≤ 约 7 字/秒。
- 不在场景切点跨条：切点前 0.2 秒内结束，切点后 0.1 秒再起。
- 一条字幕只表达一个动作或判断，句末不加句号。
- 字幕是“解说”，不是标题复读：标题给判断，字幕给过程。
- 片头 2–3 秒只留片名，不急着上字幕；最后一条在结束前 2–4 秒收住。
- 缩短片长时先减条数，不要把所有字幕压成 1 秒以内：30s 片 ≤ 12 条，15s 片 ≤ 7 条。
- 字幕由 `js/subtitle.js` 与 `timeline.js` 统一挂载；场景里不要自己画字幕，也不要改字幕颜色。

检查方法：`npm run check` 查顺序、重叠、越界、单条时长、阅读速度与跨切点；`npm run qa:layout` 量字幕是否压字/出框；`npm run qa:timing` 核对“该出现时出现、不该出现时没有”；`npm run qa` 抽帧看实际观感。字幕位置与主题样式在 `styles/base.css` + `styles/themes/*.css`。

## 8. 几种常见 brief 的故事化走法

### 产品宣传（30–60s）

产品是道具，主角是使用它的人。故事骨架：用之前被什么卡住 → 第一次使用 → 一个具体细节说服了他 → 用之后的状态。画面用产品特写、材质对比、使用动作，不要用伪 UI 硬凑。

### 功能/软件讲解（60–90s）

主角是“正在被卡住的人”，每一拍解决一个卡点，而不是念功能清单。
先写一句任务：**谁，要完成什么任务，卡在哪，谁接手。** 再按
`product-film-grammar.md` 排屏幕长镜：7–10 镜、屏幕 8–16s、间幕卡 1.93s，
所有长度量化到 1.93s。有真实界面就用真实界面（自有/授权页面抓帧），
没有就用 `screen-kit` 手搭发布级界面；每个功能只给一个镜头，
不要在一个画面里塞三个卖点。皮肤按本片品牌重定，不继承参考片。

### 活动/品牌开场（15–30s）

主角是“到场的人”。故事压缩成三段：来之前（期待）→ 在现场（一个具体瞬间）→ 离开时（带走什么）。少讲故事细节，多给时间、地点、名字；字幕承担大部分信息量。

### 人物/概念片（30–60s）

主角可以不是人：一条线、一封信、一个反复出现的声音、一个地方。靠它的移动或变化串起画面，最后回到开头的地点或物件，形成闭环。DeepSeek 的三支概念片分别用了“终端里的检索者 / 档案馆记录员 / 一条蓝线”三种主角，结构完全不同。

## 9. 反模板自检

写完分镜表，先过这四问：

1. **换名测试**：把品牌名换成另一个同类品牌，故事是否仍然完全成立？成立就说明太通用。
2. **推进测试**：每一拍是否推进了“主角—欲望—阻力—改变”中的某一环？有哪一拍删掉也不影响故事，就删掉。
3. **世界测试**：场景、道具、画面语言是否来自这支片自己的世界？如果只是上一支片的纸面/蓝线/终端换了个颜色，重写。
4. **系列测试**：连续三支片是否用了同一套场景顺序、同一套构图、同一套转场？如果是，说明又在套骨架。

### 如果你用了 `--demo` 示例

`--demo` 复制的是老的七场编辑排版示例（剪辑/软件语境）。只允许拿它研究场景契约、组件与 QA 写法；真要基于它改，必须整组换成你的行业术语，不能只改页眉：

| 示例原词 | 咖啡 | 软件 | 活动 | 护肤 |
|---|---|---|---|---|
| 素材 | 豆单 / 产地 | 数据源 | 嘉宾 | 成分 |
| 时间线 | 冲煮流程 | 工作流 | 日程 | 护理步骤 |
| 字幕 | 风味笔记 | 提示文本 | 串场词 | 使用说明 |
| 关键帧 | 注水节点 | 版本节点 | 彩排节点 | 吸收节点 |
| 素材库 | 豆仓 | 组件库 | 物料库 | 配方库 |
| 导出 | 出杯 | 发布 | 开场 | 上脸 |
| 付印单 | 冲煮单 | 发布单 | 执行单 | 配方单 |
| 262 件 | 12 支豆 | 128 个组件 | 36 位嘉宾 | 24 个 SKU |

做不到整组替换时，回到空白起步，按自己的故事重写场景。

## 10. 交稿前自检

- [ ] 有一句话能说清的故事：主角、欲望、阻力、改变都具体。
- [ ] 拍数与时长匹配；每一拍推进故事，没有并列的卖点堆叠。
- [ ] 每拍都有屏幕文案，字幕与标题不重复。
- [ ] 片名在片头、片尾各出现一次；slogan 只在片尾。
- [ ] 所有数字/日期/品牌名一致（不要一处 2026、一处 2025）。
- [ ] 字幕不跨切点；60s 基准下最短 1.2s、最长 2.4s，阅读速度 ≤ 约 7 字/秒。
- [ ] 字幕全部用 `{scene,at,dur}` 场景内定位，没有残留旧 `{start,end}`。
- [ ] 场景 id 与 index.html 引用一致，场景数量与分镜表一致。
- [ ] 调性与主题一致（安静 → `quiet`/`letterpress`；理性 → `swiss`；技术 → `tech`）。
- [ ] 没有空词、没有中英混排抢主视觉。
- [ ] 反模板四问全部通过；没有复用上一支片的场景顺序或画面。
- [ ] 读一遍总时长：按每秒 4–5 个汉字估算，字幕总字数与时长匹配。
- [ ] 缩短片长后已减条数，没有把单条压到 1 秒以内。
