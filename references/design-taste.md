# 设计品味：把 15 个设计 Skill 的共识压成可执行的规矩

这些规则不依赖具体库，全部能落在本工程的 CSS 令牌与场景节奏上。看 brief 时先过一遍，改画面前再过一遍。

## 1. 先避免“AI 味”，再谈风格

观众对“AI 做的”有固定识别特征。逐条排除：

- 默认紫蓝渐变、霓虹发光、玻璃拟态、大面积模糊背景。
- 居中一切：标题居中、副题居中、按钮居中、三张卡片居中。
- 满屏圆角卡片 + 阴影 + emoji 图标；圆角、阴影、描边三种同时上。
- 空词堆砌：“赋能、引领、革新、一站式、极致体验”。
- 无意义的 01/02/03、假数据、假 logo 墙。
- 字体只有 Inter/Roboto 一种声音；中文标题用系统默认黑体还不加字重。
- 动效从头动到尾，没有静止，没有让观众读字的间隙。

风格不是加装饰，而是**持续做减法**：一帧只允许一个焦点、一个强调色、一种主动效。

## 2. 字体

- **两种声音足够**：标题族 + 正文族；最多再加 mono 做微标签。不要三种以上字体。
- 中文标题优先宋体（`letterpress`/`cinema`/`quiet`）或粗黑（`swiss`/`tech`）；英文只做全大写微标签，字距 0.18–0.3em。
- 字号阶梯固定：`148 / 92 / 58 / 31 / 20 / 12`（1080p 基准）。标题与副题 ≥ 2.5×，副题与微标签 ≥ 2×。不要出现 3 种以上中间字号。
- 行高：大标题 1.02–1.12；副题 1.4；正文 1.6–1.8；字幕 1.25。
- 中文正文每行 ≤ 28 字，标题每行 ≤ 8 字；超过就换行或删字。
- 中文标点做光学收紧：`，。、；：！？` 右侧、`「『（《` 左侧给 -0.36em 边距。
- 数字用 `font-variant-numeric: tabular-nums`，计数器不抖动。
- 不要拉伸、压扁字体；不要给正文加描边或投影。

## 3. 间距与网格

- 只用 4/8 的倍数：`4 8 12 16 24 32 48 64 96 120`。禁止 13px、27px 这类“手感值”。
- 画面留白 ≥ 40%。信息密度高时优先删内容，不是缩字号。
- 一条对齐脊：左对齐为主；标题、正文、列表共用同一条左边距（120px）。只有片头/片尾的片名可以居中。
- 12 栏网格，内容跨 6–8 栏；右侧视觉区从 760–900px 开始，不要压到文字栏。
- 相邻元素用间距分组，不靠分隔线；分隔线只在表格/规格表里用 1px `--hair`。
- 页边距大于元素间距，元素间距大于行内间距——层级靠距离表达。

## 4. 色彩

- 一个强调色，面积 ≤ 5%（`cinema` 的金色线、`tech` 的青色信号同理）。
- 中性色阶至少 5 级：纸、纸暗、正文、次文、弱信息；不要用同一个灰承担所有层级。
- 深色底不用纯黑 `#000`，用带色相的近黑；浅色底不用纯白，用带暖/冷偏移的纸白。
- 强调色只给：编号、进度、关键数字、印章、一个图形焦点。同一画面两个强调元素必须成组，否则删一个。
- 对比度：正文 ≥ 7:1，大字/线框 ≥ 3:1；深色主题避免纯白正文。
- 颜色不承担唯一信息：图表/状态同时给形状或文字，不做红绿二元编码。

## 5. 层级

- 一帧最多三级：主标题 → 副题 → 微标签/正文。第四级就是噪音。
- 一个视觉焦点：人眼先看标题，再看图，再看字幕；不要让插画和标题同样重。
- 用“大小 + 字重 + 颜色 + 留白”四选二表达层级，不要四个一起拉满。
- 卡片网格保持等宽、等高、同基线；宁可 6 张整齐，不要 8 张错位。
- 信息沿 Z 或 F 路径排：左上角品牌/编号，主体在左中，视觉证据在右，结论在底部。
- 页眉/页脚是“版面骨架”，切点前后必须稳定；不要每场换位置。

## 6. 动效

- 入场 0.35–0.6s，用 `E.outCubic`；大位移用 `E.outExpo`；回弹只用 `E.backOut` 且幅度极小。
- **65% 法则**：一个场景的主动效在场景时长的 65% 前收住，留最后 35% 给观众读字。
- 一 scene 一个主动效：标题揭示或内容入场，二选一为主；其余只做轻微跟随。
- 错峰 40–80ms，不超过 8 个元素同时动。
- 位移 ≤ 90px，缩放 ≤ 3%；不要整场缩放叠加 timeline 运镜。
- 禁止：弹跳、抖动、旋转 3D、无限循环发光、视差叠视差。
- 切点靠硬切 + 纸色闪白；转场集中在一处调，场景里不写 transition/animation。

## 7. 节奏

- 每 2–4 秒一个信息动作；每 8–12 秒换一次画面结构（左文右图 → 全宽面板 → 数据表）。
- 场景长度 4–12s；60s 片 7 个场景是安全区。
- 密度要有高低：信息密集的场景之后接一个“呼吸场景”（片名、空镜、单个数字）。
- 片头 2–3 秒只留片名/主张；片尾 3–5 秒只留片名 + slogan。
- 字幕是节拍器：一条一个动作，读完刚好切下一句。

## 8. 从 brief 提取品牌令牌

不要问“你喜欢什么颜色”，从 brief 的名词、场景、受众里推：

| brief 线索 | 推断 | 落地 |
|---|---|---|
| 行业（咖啡/银行/芯片） | 材质与温度 | 纸色/深色底、serif 或 grotesk |
| 受众（客户/开发者/评委） | 信息密度与语气 | 编辑感 / 仪表盘 / 作品集 |
| 动词（冲、编译、守护） | 动效隐喻 | 注水式上推 / 光标扫描 / 呼吸脉冲 |
| 已有品牌色 | 强调色 | 只改 `--accent` 与 `--accent-2` |
| 交付场景（大屏/手机） | 字号与安全区 | 4K 放映 / 竖屏重排 |

三个形容词就能定一套令牌：例如“安静、讲究、日常” → 暖白纸 + 宋体 500 + 鼠尾草绿 + 2px 圆角（`quiet`）。

## 9. 收尾 polish 清单

发布前按顺序过：

1. 任一帧截图发到手机：标题 2 秒能读完吗？
2. 遮住动效只看静态版式：像一张能发出去的版面吗？
3. 强调色是否只出现在一个地方？
4. 页眉/页脚/裁切线在切点前后是否一致？
5. 有没有半截字、出框卡片、压住字幕？
6. 字幕与标题是否在说同一句话（重复 = 浪费一拍）？
7. 最后一帧是否干净、可当封面？
8. 把音量调到 30%：音乐是否只做底、不抢字幕节奏？
9. 全片扫一遍伪 UI 术语：有没有留下“剪辑软件广告”的痕迹？
10. 删掉任意一个装饰元素，画面是否更好？如果是，删。

## 10. 这些规则来自哪里

- **Taste Skill / Impeccable**：先反俗套，再做精修；强调“删”而不是“加”。
- **perfect-ui / premium-web-design / refactoring-ui-skill**：间距尺度、字号阶梯、层级与对比。
- **@theylovlj/ui-skill / designer-skills / ux-ui-agent-skills**：版式骨架、组件一致性、交付前检查。
- **Anthropic 官方 Skills**：把流程写成可执行步骤 + 验证门，而不是审美口号。
- **Hallmark / garden-skills**：一套视觉系统要有明确气质与可复用令牌。
- **GSAP Skills / oil-motion**：缓动与节奏，动效必须服务阅读。
- **UI UX Pro Max**：信息架构先于装饰，一屏一个任务。

用法：这些是“检查表”，不是“风格库”。真正决定片子长相的，是 brief 的气质 + 本工程的 5 个主题令牌。
