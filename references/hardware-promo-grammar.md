# 硬件 / 实体产品片语法 · 世界先行

> 适用：笔记本、手机、耳机、相机、家电、汽车、设备、穿戴。
> 不适用：纯软件 / SaaS / AI 平台——那些走 `product-film-grammar.md` 的真屏语法。
>
> **判据：产品自己有没有屏幕不重要，重要的是观众该看产品还是该看屏幕。**
> 卖硬件时，产品活在真实世界里；屏幕最多是一个节拍。

---

## 1. 一句话

硬件片的明星是**产品在真实环境里的样子**：光落在铝壳上、合盖的一声、键盘背光在暗处亮起。
把 90% 的时长交给屏幕 UI，拍出来的就不是硬件宣传片，是功能演示。

反面病例（2026-11 MacBook 片）：90% 镜头是屏幕、青色占 82%、全片 2 个色域、43% 静止帧。
观众的结论是“演示了一个功能”，不是“想拥有这台机器”。

---

## 2. 结构（60s）

| 段 | 时长 | 内容 | 关键 |
|---|---|---|---|
| 世界 | 0–8s | 空间、光、人的痕迹；产品未出现或只是剪影 | 第一眼要看到“地方”，不是黑底 |
| 仪式 | 8–18s | 掀盖 / 点亮 / 拿起 / 合盖；动作 > 功能 | 手部特写 + 磁吸声 |
| 细节 | 18–32s | 材质、铰链、键帽、接口、背光、风扇 | 微距 1–2cm，比全景更“贵” |
| 使用 | 32–44s | 人在环境里使用；屏幕只做 1–2 个短节拍 | 屏幕出现必须带来新状态 |
| 结果 | 44–54s | 做完的事、留下的痕迹、离开 | 杯子的圆环、便签、合盖后的一口气 |
| 收束 | 54–60s | 产品回到环境 / 字标 | 环境不能消失，别回到黑底 |

## 3. 画面配方（全代码绘制）

### 3.1 三层空间

每一镜至少三层，各有不同运动速度（视差）：

1. **远景**：窗/墙/城市/天空/树影——大面积渐变 + 柔焦；
2. **中景**：桌面/台灯/杯子/书本/椅背——实体色块 + 接触阴影；
3. **近景**：产品，或手 + 产品。

只有一层 = 贴图感；三层 + 视差 = 空间。

### 3.2 光

- 一个主光方向（窗、台灯、屏幕）+ 一个环境光（墙面的反弹光）；
- 光要**有形状**：窗格光斑、百叶条纹、屏幕的矩形冷光；
- 产品边缘给一条 1–2px 的轮廓光（rim light），铝壳才“立”起来；
- 暗部不要死黑：留 6–10% 的冷色环境光。

### 3.3 材质

| 材质 | 画法 | 别做 |
|---|---|---|
| 铝 / 金属 | 多段线性渐变 + 一条高光带 + 细噪点 | 单一灰色块、塑料感 |
| 屏幕玻璃 | 深底 + 低对比反射条纹 + 边缘高光 | 纯黑矩形、镜面倒影 |
| 键盘 | 逐键凹槽（内阴影）+ 背光透出 | 一整块深色矩形 |
| 木桌 | 横向色带 + 长纹理 + 使用痕迹 | 纯色平面 |
| 织物 | 细噪点 + 柔和大褶皱 | 硬边色块 |
| 纸 | 米白 + 微黄边 + 折痕 | 纯白 |

### 3.4 真实感的四个小东西

- **接触阴影**：产品落在桌面上的暗部，边缘柔、中心深；
- **微尘**：光源里的 20–40 个 1px 粒子，缓慢漂移；
- **景深**：远景 `blur(6–10px)`、中景 `blur(2–4px)`、近景清晰；
- **颗粒**：全片 2–3% 噪点 + 暗角，压掉“矢量图”的干净感。

### 3.5 人

只画**手、剪影、背影、局部**；不画正脸（代码画脸必假）。
人的作用：给产品一个尺度、一个使用者、一点体温。

### 3.6 屏幕

- 屏幕镜头不设硬配额；经验上别超过三成，且每次出现必须是“状态变化”：亮起、锁屏、一条消息、合盖前的最后一眼；
- 屏幕内容不需要演示功能流程；一个壁纸 + 一个动作就够；
- UI 演示属于软件片的语法，不属于硬件片。

### 3.7 代码零件库 `js/product-kit.js`

不要每支片从零画桌子。模板自带 `window.product`，全部 CSS/SVG 绘制，`seek(local, slot)` 只依赖时间，可逐帧复现；`styles/product.css` 已随模板引入。

```js
// 场景 mount 里
const shot = product.hardwareShot({
  place: 'loft',            // loft（默认）| studio | cafe | night
  tone: 'dawn',             // dawn（默认）| day | dusk | night
  light: 'left',            // left（默认）| right
  props: ['mug', 'notebook', 'plant'],   // mug | notebook | plant | lamp | paper | chair
  device: 'laptop',         // laptop（默认）| none（只拍空间/手/道具）
  material: 'silver',       // silver（默认）| space | gold
  angle: 'left',            // left（默认）| right
  framing: 'mid',           // wide | mid（默认）| close | macro
  focus: 'auto',            // auto（默认）| center | edge | screen
  move: 'push',             // push（默认）| pan | rise | drift | handheld
  screen: 'lock',           // off | lock（默认）| glow | ui
  open: { from: 0.18, to: 1 },   // 开合：数字或 {from,to}
  sweep: { from: 0.1, to: 0.9 }  // 光扫：数字或 {from,to}
});
root.appendChild(shot.node);
// seek(local, slot)：shot.seek(local, slot)；slot 是这一镜的真实秒数
// 需要状态变化时：shot.setScreen('glow') / shot.setOpen(0.7)
```

- 三层视差、窗光柱、浮尘、桌面接触阴影、键帽/铝壳/屏幕渐变都在套件里；**你的工作是把镜头排成故事**，不是重画电脑。
- `product.space({ place, tone, light, props, dust, grain })` 只给空间（建立镜头、空镜转场）；`product.laptop({ material, screen, angle, open })` 只给设备（需要自己摆机位时）。
- 只支持 16:9；竖屏会在控制台警告，请改用编辑版式或重排空间。
- 套件不是免检：`npm run qa:layout`、`npm run qa:timing`、`npm run repair` 仍要看；`framing:'macro'` 时尤其检查顶角、铰链与桌面接触阴影是否完整。
- 同一支片里换 `place`/`tone` 就是换空间与光——至少用 3 个 place、3 个 tone，避免全片一间房。

## 4. 镜头语言

| 镜头 | 做法 | 时长 |
|---|---|---|
| 空间建立 | 缓慢横移 + 三层视差 | 3–5s |
| 产品入场 | 从焦外推进到合焦，或光先到、产品后现 | 2–3s |
| 微距细节 | 1–2cm 的键帽/铰链/接口，浅景深 | 1.5–2.5s |
| 光扫 | 高光沿铝边滑过，1.5–2s | 1.5–2s |
| 开合 | 铰链角度连续变化 + 屏幕渐亮 | 2–3s |
| 使用 | 手 + 产品 + 环境，中景 | 3–4s |
| 收束 | 拉远回到空间，产品或光留在画面里 | 3–4s |

运动规则：全片没有完全静止的镜头；切点硬切或光/遮挡转场；相邻镜头的空间、光、景别至少换两个。

## 5. 色彩脚本（硬性）

- ≥ 4 组色板，每组标：主色 token、光、情绪、用在哪几场、预计时长占比；
- 主色域占比 ≤ 60%（`npm run qa:variety`），色域数 ≥ 3；
- 明暗跨度 p90−p10 ≥ 0.10；不要全片一个亮度；
- 推荐一条时间色温线：冷（夜/晨）→ 暖（日光/黄昏）→ 冷（夜）→ 中性（收束），或反过来；
- 产品自身的颜色（铝、黑、白）是锚点，环境色围绕它变化，不要给产品染色。

## 6. 反模式

| 反模式 | 为什么假 | 改成 |
|---|---|---|
| 深色渐变上的悬浮产品 | 没有世界，像渲染图 | 三层空间 + 光 + 接触阴影 |
| 九成时间拍屏幕 | 变成功能演示 | 屏幕只做节拍、每次只带一个状态；超过三成会提示，确认是有意为之即可 |
| 一套颜色到底 | 单调、廉价 | 4–6 组色板，随情绪推进 |
| 产品不动、镜头不动 | 像产品目录 | 每 1.5s 有变化：光、尘、手、呼吸 |
| 用字幕说“轻薄/强大” | 说明文不是广告 | 拍合盖的厚度、单手拿起 |
| 正面大特写产品居中 | 像电商主图 | 偏置构图 + 留白 + 环境 |
| 光打成平光 | 失去体积 | 主光 + 环境光 + 轮廓光 |

## 7. 验收

1. **3 秒测试**：第一眼看到的是“一个地方”还是“一张 PPT”？只有前者算过。
2. **遮屏测试**：随机抽 6 帧，是否有 ≥ 3 个不同空间？不够就补世界镜头。
3. **灰度测试**：去色后明暗层次仍成立；不成立说明靠颜色硬撑。
4. **静音测试**：关掉音乐与字幕，动作仍讲得通。
5. **机器判据**：`npm run check` 里的分镜契约（`config.grammar = 'world'` + `config.shots`）必须过：≥4 空间、微距 ≥2、人迹 ≥2、相邻镜不同空间+主体+景别；屏幕占比只做诊断（超过 30% 只警告，不拦交付）；`qa:motion` 静止帧 < 25% 且无 ≥1.2s 静止段；`qa:variety` 主色域 ≤ 60%、色域 ≥ 3、明暗跨度 ≥ 0.10。
6. **换名测试**：换一个同类产品，画面仍成立 = 拍的是品类不是这支片；要重做空间与细节。

---

## 8. 与真屏语法的边界

- 软件 / AI / 平台产品：`product-film-grammar.md`，全出血界面 + 一条任务；
- 硬件 / 实体产品：本文档，世界 + 仪式 + 细节 + 使用；
- 软硬结合（如硬件 + 自带系统）：以硬件为主，屏幕只做节拍（经验上不超过三成）；不要两头都拍成半支片。
- 两种语法不共用镜头结构；同一支片里不要来回切换“演示模式”和“世界模式”。
