# 七问定向：先弄明白制作人的意思

七问不是让制作人替 AI 写片，也不是一张必须填满的需求表。它只做一件事：在动笔前把**意图、对象、记忆点、禁忌和交付条件**对齐。故事、镜头、颜色、节奏仍然由 AI 提案；七问定方向，细节靠追问，最后用回述确认理解。

七问必须走完，但**不要把七个问题问成七轮审讯**：第 1 问单独问；第 2–5 问放一张卡片；第 6–7 问放一张卡片。brief 里已经说清楚的，不再问，在回述里标「已知」。用户说「你定 / 随便」时，给 2–3 个具体方案与取舍，推荐一个，让用户确认；不要用一句「已按默认处理」跳过。

## 通用规则

1. **第 1 问永远先定类型**：宣传片 `promo`、MV `mv` 还是 3D 短剧 `story`。用编辑器的选择器（问题/选项卡片、ask_user、提问工具），不要发纯文本让用户回编号。
2. **选项要有画面感**：每个选项写「是什么 + 会得到什么」，不要只写抽象标签。选择器自带「其他」时直接用；没有就补一个「其他（我来说）」。
3. **七问只定方向**：不要问镜头、景别、颜色值、字体、转场、运镜。这些由 AI 在 treatment 与分镜里提案，再用静帧给用户看。
4. **追问只为结构**：七问之后最多 2 轮细节追问，每轮 ≤3 问；只问那些答案会改变故事、人物关系、空间或交付格式的问题。下一问不会改变片子，就停止追问。
5. **先回述再动笔**：七问结束后，用 5 行复述你的理解，再用一句话说出你准备写的故事，等用户确认或纠正。确认后才写 `treatment.md`。
6. **答案不能丢**：把七问与追问的答案写进 `direction.json`，建工程时传 `--intake direction.json`。后续 treatment、分镜、文案不得与它矛盾；要改方向，先改 `direction.json` 并重新确认。

## 宣传片（promo）七问

| # | 问题 | 选择器选项（id） | 它决定什么 |
|---|---|---|---|
| 1 | 这支片属于哪一种？ | 宣传片 `promo` · MV `mv` · 3D 短剧 `story` | 语法、模板、QA；选错后面全错 |
| 2 | 这支片的主角是什么？ | 软件 / AI / 平台 `software` · 硬件 / 实体产品 `hardware` · 空间 / 场所 / 服务 `space` · 人物 / 团队 / 理念 `people` | 真屏语法还是世界语法；`config.grammar`；镜头里屏幕能占多少 |
| 3 | 给谁看，看完你希望他们做什么？ | 潜在客户 `consumer` · 专业客户 / 合作方 `pro` · 内部 / 投资人 `internal` · 公众 / 社媒 `public` | 信息密度、语气、证据类型、结尾 CTA |
| 4 | 如果观众只记住一个东西，你希望是什么？ | 一个具体时刻 `moment` · 产品被使用的一瞬 `use` · 一个麻烦被解决 `problem` · 一种生活方式 `lifestyle` | 故事种子与情绪落点；不是完整故事 |
| 5 | 你想要什么气质？ | 先选气质分组，再选具体 look（15 个方向） | 主题、版式、动效、引擎；由用户选定，AI 只排序推荐 |
| 6 | 你最怕这支片变成什么？ | 功能演示 / 只拍屏幕 · 城市空镜集 · 产品参数目录 · 空洞的品牌隐喻诗（可多选） | 方向锁的「这不是」；这是最有效的防跑偏锚点 |
| 7 | 交付形态是什么？ | 60s · 16:9 · 合成乐 · 无旁白 `60-16x9` · 30s · 16:9 · 中文口播 `30-16x9` · 30s · 9:16 · 合成乐 `30-9x16` · 15s · 9:16 · 合成乐 `15-9x16` | 时长、画幅、声音；素材来源在细节追问里补 |

第 5 问的两轮选择器见 `looks.md`：第一轮选气质分组，第二轮选具体 look；推荐项标「推荐」，但不要替用户拍板。用户明确说「你定 / 随便 / 自动」时才用 `auto`，并在交付时说明。

### promo 的细节追问（最多 2 轮，每轮 ≤3 问）

- 产品 / 服务具体做什么？用户第一次接触时最容易误解成什么？
- 有没有必须出现的真实细节（手、材质、工序、地点、道具）？有没有绝对不能出现的东西（竞品、真人、某个词、某类场景）？
- 有没有参考片或喜欢的东西？只学它的方法（构图、节奏、光线），不复制角色、台词与品牌资产。
- 投放在哪（官网 / 发布会 / 抖音 / 展会）？有没有截止时间、品牌规范或必须保留的字标？

不要问「你想要什么颜色 / 什么字体 / 几个镜头」。AI 先给方案，再让用户改。

## MV 七问

| # | 问题 | 选择器选项（id） | 它决定什么 |
|---|---|---|---|
| 1 | 这支片属于哪一种？ | 宣传片 `promo` · MV `mv` · 3D 短剧 `story` | 语法、模板、QA |
| 2 | 歌 / 声音从哪来？ | 成品歌 + 歌词 `song` · 纯音乐 `instrumental` · 还没有音乐 `synth` · 静音 `silent` | 歌词来源、`npm run song`、声音设计；静音也要有画面内文字 |
| 3 | 这是谁的故事？ | 一个人 `one` · 两个人 `two` · 一群人 `ensemble` · 一个地方 / 物件的视角 `object` | 人物数量与关系骨架；MV 需要 2–3 个有关系的人 |
| 4 | 他 / 她最想要什么，什么挡着？ | 等一个人回来 `wait` · 离开熟悉的地方 `leave` · 守住一件东西 `keep` · 找回一段记忆 / 一个人 `remember` | 故事引擎；AI 再补「怕什么 / 不肯说 / 必须做的选择 / 最后的改变」 |
| 5 | 最后一个镜头，你希望停在什么情绪？ | 重逢 `reunion` · 释然 / 放下 `release` · 继续上路 `continue` · 没有答案但人变了 `open` | 结局与情绪落点；不是让用户写结局 |
| 6 | 你最怕这支 MV 变成什么？ | 纯空镜风景片 · 歌词配图 · 抽象诗 · 角色走过场（可多选） | 方向锁的「这不是」；防止空镜堆叠 |
| 7 | 你想要什么情绪走向？ | 黄昏 → 夜 → 风暴 → 黎明 `dusk-night-storm-dawn` · 白昼 → 黄昏 → 深夜 `day-dusk-night` · 冷雨 → 暖室 → 雪停 `rain-warm-snow` · 其他 | mood 弧线；AI 再定四段歌词、母题与镜头 |

第 4 问只问「想要什么 + 什么挡着」，不要追问人物小传。人物小传由 AI 在 treatment 里写，写完给用户看。

### MV 的细节追问（最多 2 轮，每轮 ≤3 问）

- 第二个人是谁，和主角什么关系？谁在等谁，谁欠谁？
- 歌里哪一句是转折？有没有必须保留的歌词或画面？
- 哪个母题 / 道具要出现三次（灯、船、信、花、窗、车票）？天气要不要参与叙事？
- 结局是重逢还是错过？最后一个镜头与第一个镜头有什么不同？
- 有成品歌时：音频与歌词文件在哪？先跑 `npm run song -- --dry-run` 核对时间轴。

不要问「几个镜头 / 什么景别 / 用什么颜色」。MV 的镜头与 mood 由 AI 按 `mv-craft.md` 提案。

## 3D 短剧（story）七问

| # | 问题 | 选择器选项（id） | 它决定什么 |
|---|---|---|---|
| 1 | 这支片属于哪一种？ | 宣传片 `promo` · MV `mv` · 3D 短剧 `story` | 语法、模板、QA |
| 2 | 这一集只回答哪一个问题？ | 等一个人 / 一句话 `wait` · 要不要走 `leave` · 认不认得出来 `remember` · 该不该回来 `return` | 一集一个钩子；AI 再把它说具体（谁、在等什么、卡在哪） |
| 3 | 这一集有几个人？ | 两个人 `two` · 三个人 `three` · 四个人 `four` | cast 数量与声线数量；每个角色一句身份与关系 |
| 4 | 主角想要什么，什么挡着？ | 自由填写 | 故事引擎；必须是画面能看见的动作/物件 |
| 5 | 什么挡着他 / 她？ | 自由填写 | 阻力；必须是这场戏里能看见的东西 |
| 6 | 最后停在哪？ | 暖 `warm` · 开放 `open` · 苦甜 `bittersweet` · 反转 `turn` | 结局与最后一镜；`titleCard.hook` 由 AI 写 |
| 7 | 声音怎么做？交付多长？ | 多角色配音 + 合成乐 `multi` · 单人旁白 `single` · 静音只靠字幕 `silent`；40s / 60s / 90s · 16:9 `40-16x9` / `60-16x9` / `90-16x9` | 配音流程与交付规格；story 只做 1080p 横屏 |

story 不问画幅与分辨率：固定 1920×1080 横屏、1080p；3D 赛道不做竖屏，用户要 9:16 时改走 promo 或另做模板。第 4–5 问不要问成人物小传，只问「想要什么 + 什么挡着」；人物小传由 AI 在 treatment 里写。

### story 的细节追问（最多 2 轮，每轮 ≤3 问）

- 这场戏在哪儿发生？时间、天气、光线是什么？有没有必须出现的道具（碗、伞、信、手机）？
- 谁先开口？哪一句是转折？有没有必须保留的台词？
- 结局是接住了还是错过了？最后一个镜头与第一个镜头有什么不同？
- 平台是抖音 / 快手 / 视频号？有没有系列名、集数或片尾钩子要求？

不要问「几个镜头 / 什么景别 / 用什么颜色 / 用什么语音」。镜头与声线由 AI 按 `story-drama.md` 提案。

## 回述模板

七问之后，先不要写 treatment。用下面 5 行 + 一句话故事复述，等用户确认：

```text
我理解的方向：
- 类型：宣传片 / MV
- 给谁看 / 看完做什么：……
- 主角与唯一记忆点：……
- 气质与禁忌：……（最怕变成……）
- 交付：60s · 16:9 · 1080p · 合成乐 / 无旁白
- 我准备写的故事：……（一句话：谁想要什么、被什么挡住、最后改变了什么）
哪里不对直接改我；没问题我就按这个写 treatment。
```

MV 把「给谁看 / 看完做什么」换成「这是谁的故事 / 最后停在什么情绪」；story 换成「这一集回答什么 / 谁想要什么、什么挡着 / 停在哪」。回述不是复读选项，要用你自己的话把因果说出来；如果说不成一句话，说明还没理解，继续问。

## direction.json

七问答案用一份 JSON 保存，建工程时传给 `--intake`：

```bash
node scripts/new-film.js ./my-film --intake direction.json --title "北岸咖啡"
```

`new-film.js` 会把答案写进工程根目录的 `direction.json`，并把方向锁预填进 `treatment.md`。没有 `--intake`、又不在终端里时，它会直接报错，提示先问完七问——不要绕过。

### promo 示例

```json
{
  "genre": "promo",
  "subject": "hardware",
  "subjectNote": "一台笔记本，在真实房间里被写作者使用",
  "audience": "pro",
  "audienceNote": "自由职业者与创意工作者",
  "memory": "moment",
  "memoryNote": "合盖前，手指在键盘上停了一秒",
  "look": "quiet-editorial",
  "avoid": ["功能演示 / 只拍屏幕", "城市空镜集"],
  "format": "60-16x9",
  "audio": "synth",
  "materials": "none"
}
```

### MV 示例

```json
{
  "genre": "mv",
  "music": "song",
  "musicNote": "用户提供 mp3 + lrc",
  "protagonist": "two",
  "protagonistNote": "守灯的女儿与多年未归的父亲",
  "want": "wait",
  "wantNote": "她想让父亲看见灯还亮着",
  "ending": "reunion",
  "endingNote": "船进港，她哭着笑",
  "avoid": ["纯空镜风景片", "歌词配图"],
  "moodArc": "dusk-night-storm-dawn",
  "reference": "（可选）"
}
```

### story 示例

```json
{
  "genre": "story",
  "format": "40-16x9",
  "hook": "wait",
  "hookNote": "她在面摊多要了一碗面，等一个说马上到的人",
  "people": "two",
  "peopleNote": "她：先到的那个；他：总说马上到的人",
  "want": "多要一碗面，摆在对面的位置",
  "obstacle": "雨越下越大，他的消息停在「正在输入」",
  "ending": "bittersweet",
  "endingNote": "他赶到时面已凉，她推过去说坐吧",
  "voice": "multi",
  "avoid": ["纯空镜风景片", "台词像解说"]
}
```

字段 id 必须来自上面的选项；`look` 必须是 `tools/pick-look.js --list` 里的 id，或 `auto`（仅当用户明确授权代选，并加 `"lookAuthorized": true`）。`avoid` 写用户的原话或选项文案，不要编造。`subjectNote / audienceNote / memoryNote / protagonistNote / wantNote / endingNote / hookNote / peopleNote` 是可选的补充，用用户的原话最好。story 的 `format` 只接受 `40-16x9 / 60-16x9 / 90-16x9` 横屏，不接受 9:16 与 4K。

生成空白骨架：

```bash
node scripts/new-film.js --intake-template promo
node scripts/new-film.js --intake-template mv
node scripts/new-film.js --intake-template story
```

## 常见错误

| 症状 | 原因 | 修法 |
|---|---|---|
| 只问了类型就建工程 | 把「第一道分叉」当成全部七问 | 建工程前必须拿到完整 `direction.json`；非终端会被 CLI 拒绝 |
| 七问问成了审讯 | 一次只问一个，或追问镜头/颜色 | 第 1 问单独；第 2–5、6–7 各一张卡片；细节追问最多 2 轮 |
| 用户说「随便」就全自动 | 把授权当成不用理解 | 给 2–3 个具体方案与取舍，推荐一个，让用户确认 |
| treatment 和七问矛盾 | 七问答案没写进 `direction.json`，或写稿时没看 | 先改 `direction.json` 并重新确认，再改 treatment |
| 把 MV 的问题拿去问宣传片 | 两套语法混用 | 按类型只读对应那一列；选项 id 不通用 |
| 把 story 问成剧情大纲 / 人物小传 | 把七问当成剧本 | story 只问「这一集回答什么 / 想要什么 / 什么挡着 / 停在哪」，人物与台词由 AI 写 |
| 七问答案变成了故事 | 把「一个具体时刻」直接当剧本 | 七问只给种子；人物、关系、故事弧、镜头仍要写透 |
