# MV 制作经验（paper-story，层叠剪纸叙事）

这份文档只记**可复用的做法**，不绑定任何一支具体片子。引擎层通用；故事、港口、角色、歌词都写在内容层，换一支片就整段替换。核心审美：**一只船、一个人、一盏灯，全部是纸**——分层剪影、纸边高光、柔和投影，不追求写实，追求“手工剪纸定格”的质感。

## 0. 扩写：一句话 → 一个世界 → 人物 → 镜头

MV 的稿子要比宣传片厚得多。宣传片只写与画面有关的“世界 / 空间 / 序列 / 色域”；MV 要把**背景、人物、关系、母题、歌词段、镜头候选与 mood** 全部写透。两边都**不设字数上下限**：写得越详细越好，写到每个镜头都能直接拍为止。两套内容不能互换：宣传片的 6 空间表搬进 MV 会毁掉剪纸叙事，MV 的人物小传搬进宣传片会变成没人拍得起的设定集。

**写作轨道**：MV 是故事片。先有人，再有世界，再有歌，最后才是镜头。不要从 mood 或漂亮的空镜开始写。

### 0.1 写作顺序（不许跳到分镜）

先读工程根目录的 `direction.json`（七问答案）与回述记录。七问只给了方向，不是故事：不要重新采访用户已经回答过的事，也不要把它直接当剧本；人物、关系、故事弧、母题、歌词段与镜头仍要写透。

1. 方向锁（半小时内写完，后面每一段都回来对照）
2. 世界与背景
3. 人物与关系
4. 故事弧
5. 母题与意象
6. 歌词段
7. 镜头候选（≥32 → 20–28）
8. mood 脚本
9. 声音、片头片尾、删除日志

### 0.2 方向锁

`treatment.md` 开头必须写清这五行，防止写着写着变成一支抽象诗：

```
类型：MV · paper-story　写作轨道：故事 / 人物 / 歌词 / 镜头
主体锚点：<这是谁的故事；一句话>
情绪落点：<最后一个镜头要让观众感到什么>
这不是：<最容易跑偏的两种片，例如 纯空镜 MV / 风景明信片 / 抽象诗>
Wild card：<允许一个不推进剧情、但揭示人物内心的镜头>
创意自由度：<这个故事允许自己发明的非显然画面或结构>
```

**锚点测试**：把主角换成一个无关的人，故事应该立刻不成立。如果换谁都一样，说明人物还没有欲望与阻力。

### 0.3 世界与背景

写这个故事的**生活底色**，不是编年史，越具体越好：

- 地方与时代：海边镇、山里、旧城、未来港，或一个没有名字但质感明确的地方；写建筑、器物、衣服、交通工具。
- 社会质感：人们靠什么活着、怕什么、信什么；谁有权力，谁在等待。
- 天气与日常仪式：潮汐、季风、集市、点灯、渡船、晚饭；这些会变成 MV 里“会动的纸”。
- 只保留 **3–5 件能改变人物选择的事**。背景不是设定集，写多了拍不出来。

背景要落到可拍的名词：灯塔的铜锈、码头木桩上的盐、窗玻璃的霜、船帆的补丁。不要写“一个充满希望的小镇”。

### 0.4 人物与关系（2–3 人）

每个主要人物写六件事，一两句话就够：

- 名字 / 身份 / 识别特征（围巾、旧外套、一只手电）；
- 想要什么（具体到今晚要做的一件事）；
- 怕什么（失去谁、错过什么、被谁看见）；
- 不肯说的事（这首歌真正的隐情）；
- 这次故事里必须做的选择；
- 最后的改变（或没有改变，但要让观众看见为什么）。

这是检查表，不是人物小传模板：六件事可以合并、可以只写三件，但缺了欲望、阻力与改变，人物就立不住。不要为了填满六项去编前史。

关系写三行：**谁在等谁 / 谁欠谁 / 这次相遇或分离会改变什么**。阻力不必是反派，可以是距离、时间、职责、天气、一艘迟迟不回的船。没有关系，MV 就只剩风景。

主角镜头 ≥50%（`who` / `hands` / `hero`）；配角可以只出现在 wide 与 mid 里，但必须有自己的动作。

### 0.5 故事弧

主角是谁 → 想要什么 → 被什么挡住 → 做了什么选择 → 最后一个镜头和第一个镜头有什么不同。写不出“改变”，就还没有故事，先别写镜头。这一段可以短，但必须完整；不要用氛围描写代替事件。

### 0.6 母题与意象（3–5 个）

选 3–5 个会反复出现的物件、动作或声音：一盏灯、一条围巾、一封信、一次回头、潮声。每个母题至少出现三次，而且**每次要变**：点亮 → 熄灭 → 再点亮；围上 → 被风吹走 → 捡回来。母题不是装饰，是人物关系的可见证据。

### 0.7 歌词段（verse → chorus → bridge → finale）

有成品歌/歌词，先把每句按绝对秒数落进四段；没有歌，先写 12–18 句口语歌词（每条 8–16 字、≤7 字/秒）。歌词是人物心里的话，不是镜头说明；一句只讲一件事。四段要能各用一句话概括：**发生了什么、他做了什么、他明白了什么、最后留下什么**。

### 0.8 镜头候选（≥32 → 20–28）

60s 先写 ≥32 个候选镜，删到 20–28；每镜只发生一个动作，按 2–3 秒草拟。候选表字段：时间 / `s` / `mood` / `frame` / 这一镜发生什么 / 歌词。片长超过 60s 时按 2–3 秒一镜等比增加候选。

候选镜必须能回答“谁在做什么”，而不是“这里好看”。越多越好，不设上限：先写够，再删到 20–28。删掉的镜头与原因写进删除日志；被删的最好的画面也要记下来，下一支片可能用得上。

### 0.9 mood 脚本

`dusk / night / storm / dawn` 至少用 3 档，单一 mood 不超过 60% 的镜头；通常每档 ≥2 镜，但允许为了叙事理由打破——理由写进 treatment。相邻镜头不要同场景同景别；每个情绪段至少有一次 `wide → close` 或 `close → wide` 的呼吸。mood 对应情绪段，不是滤镜；颜色只从 `K.pal(mood)` 取，不写色值。

### 0.10 质量门槛（不过不写 `film.js`）

- 细节：背景、人物、关系、母题、歌词段、镜头候选都写到能直接拍；只有形容词的段落要重写。
- 四段歌词各有明确事件，不是四段同义反复；
- 主角镜头 ≥50%，`wide / mid / close` 三档都有，同场景重复必须换 `v`；
- 每句歌词都落在一个“有动作”的镜头里，不落在片头卡、片尾卡上；
- 至少 3 档 mood，且每档都能说出它对应哪一段情绪；
- 换名测试：把歌名、角色名换掉，分镜仍然只属于这个故事；
- 锚点测试：把主角换成无关的人，故事立刻不成立。

| 反模式 | 病因 | 修法 |
|---|---|---|
| 一句歌词一个空镜 | 把歌词当分镜 | 先写 32 个“谁在做什么”的候选镜，再让歌词去贴合 |
| 24 镜全是 wide | 只写环境，不写人 | 补 close（手/脸/火）与 mid（人与环境对半） |
| 全片只有一种 mood | 只挑好看的一档 | 按段落排 dusk→storm→dawn，主 mood ≤60% |
| 镜头里没有动作 | 画面只是背景板 | 每镜写一个动词；没有动词就换镜 |
| 有背景，没有人物 | 写了很多世界观，主角还是个剪影 | 先写人物六件事与关系三行，再删背景 |
| 有情绪，没有事件 | 四段都在“想念”，什么都没发生 | 每段写一个可拍的事件与一个选择 |
| 把 MV 当宣传片 | 加标题卡、卖点字幕、屏幕镜头 | 回到剪纸叙事；片名只出现在片头/片尾卡 |

扩写产物 `treatment.md` 放在工程根目录，先给用户看**方向锁、人物与关系、故事弧、歌词段与镜头候选**，确认后再写 `film.js`。MV 模板自带一份《把灯留着》的完整示范 treatment（33 条候选镜、4 档 mood、删除日志），可以当作格式与颗粒度的参照；`new-film.js` 建新工程时会换成为这支片准备的空白底稿，不会继承示范剧情。

**创意空间**：配额是下限，不是处方。不要照抄示范片的海港、灯塔与守灯人；地方、人物、母题都从这一支 brief 长出来。每支片允许一个 wild card 镜头，也允许在结构上发明（倒叙、同一构图三次变奏、用声音代替一次转折），只要方向锁还成立。`qa:variety` 对 MV 是提示不是审美裁判：纸色和天空会让主色域天然偏高，先看 mood 覆盖与明暗跨度，再决定是否加段落色，**不要为了指标往纸色里塞荧光色**。

## 1. 三层分离：引擎 / 内容 / 配置

| 层 | 文件 | 谁改 | 规则 |
|---|---|---|---|
| 引擎 | `js/paper-kit.js` `paper-figures.js` `paper-sets.js` `shot.js` `timeline.js` | 只在需要新场景/新角色能力时改 | **不写任何一支片专属的地名、歌词、品牌字**；文字一律从 config / script 读 |
| 内容 | `js/film.js`（分镜）、`js/script.js`（歌词与片头片尾字） | 每支片整段重写 | 示范故事只是格式样例，不是必选剧情 |
| 配置 | `js/config.js` | 建工程时写入，之后微调 | 片名/品牌/标语/`kicker`/`endTag`/分辨率/封面时间 |

判断标准：如果这段代码换一支片就不能用，它属于内容层，不属于引擎层。

## 2. 分镜数据（film.js）

- 示范模板 24 镜 × 2.5 秒 = 60 秒；成片按 treatment 定稿的 **20–28 镜**写，每镜**只发生一个动作**（她走到栏杆、她擦亮火柴、浪抬起来、船进港）。
- 每镜 2–3 秒。少于 2 秒来不及看清纸片构图，多于 3 秒情绪会停。
- 每镜唯一的 `v` 派生调色、构图与微差；**同一场景可以重复出现，但不会出现同一张画面**。
- 最后一镜 `end: true` 且 `s: 'end'`，收在 `film.total = config.base` 上。
- `SECTIONS` 只标四个情绪段：`verse`（黄昏送别）、`chorus`（风暴守灯）、`bridge`（天快亮）、`finale`（船回）。它不影响切法（全片硬切），只给写分镜时定节奏。

常用镜头字段：

```js
{ s: 'pier',   mood: 'dusk',  frame: 'mid',  who: GIRL({ x: 700, y: 930, h: 330, pose: 'stand', dir: -1 }), boat: { x: 1230, y: 800, s: 0.44 } }
{ s: 'tower',  mood: 'storm', frame: 'wide', lampOn: 1, beam: true, hero: true }
{ s: 'flame',  mood: 'night', frame: 'close', hands: true, shield: 0.55 }
{ s: 'window', mood: 'dawn',  frame: 'mid',  wipe: true, who: GIRL({ x: 980, y: 1010, h: 680, pose: 'back' }) }
{ s: 'end',    mood: 'dawn',  frame: 'wide', end: true, boat: { x: 1180, y: 760, s: 0.62 } }
```

- 场景 `s` 只能取 `paper-sets.js` 里注册的名字：`harbor / pier / portrait / tower / lamp / flame / sea / window / end`。
- `mood` 四档：`dusk` 暖橙、`night` 深蓝 + 月光、`storm` 冷灰绿、`dawn` 粉金。只在 mood 调色板里取色，不在镜头里写色值。
- `frame` 三档：`wide`（环境占 2/3）、`mid`（人与环境对半）、`close`（脸/手/火占满）。24 镜里 wide/mid/close 都要有。
- 角色统一用 `GIRL({...})`（`p: 'girl'`），pose：`stand / walk / run / back / reach / sleep`；`expr`：`calm / worry / determined / smile`。

## 3. 层叠剪纸的画法

- 一张画面 = **天空 → 远景海 → 城镇 → 中景海 → 码头/灯塔 → 人物 → 前景浪 → 纸纹/暗角 → 歌词**。顺序写死在场景函数里，不要临时插层。
- 每块纸都走 `K.paper(fill, { edge, dy, blur })`：顶部一条亮边（纸的裁口）、下方柔投影（纸与纸的间距）。没有这条边的形状会像矢量图，不像剪纸。
- 纸色全部从 `K.pal(mood)` 派生；同一画面里纸层不超过 6 层，多了会脏。
- 海面用横向长条纸 + 白色浪线；浪线只画 3–5 条，每条粗细不同，不要画成均匀网格。
- 灯塔、码头是“立起来的纸片”：正立面 + 深色侧面，顶部有 1px 亮边；灯室那盏灯是全片唯一的高饱和暖色，别的地方不许抢。
- 人物是**剪影纸人**：深色大衣 + 一条围巾做识别色；脸只在 close 镜里出现（`F.bust`），wide 镜一律用剪影，不要把小脸画进远景。

## 4. 会动的只有纸和光

没有推拉摇移。镜头固定，运动来自：

- 海的呼吸（浪的起伏、浪线漂移）、雨丝、雾的漂移、灯束的扫动、火光抖动、船随浪轻晃、人物的呼吸与围巾飘动。
- **每一帧至少有一层在动**；纯静帧会被 `qa-mv` 的 +0.45s 检查抓出来。
- 动作要在镜头 70% 前收住；最后的 30% 留给观众看清这张纸。
- 转场只有硬切（`timeline.js` 统一处理），场景里不要写淡入淡出。

## 5. 歌词（script.js）

- 底部歌词由 `K.lyric` **画在画布上**（底部安全区，约 y=940–1010），时间写绝对秒数；DOM `#subs` 只用于预览，不参与成片。
- 每条 8–16 个汉字，**≤7 字/秒**，不重叠，不越界，第一条不要压在片头卡上；句子可以跨切点。
- 只写听得懂的口语，不写镜头说明、不写术语；一句只讲一件事。
- 歌词进场淡入 0.18s、退场 0.22s（`K.cueAt` 内置），不要在场景里再给字幕加动画。

## 6. 歌曲接入（tools/song.js）

用户给了成品歌与歌词时：

```bash
npm run song -- --audio ~/Music/tide.mp3 --lyrics ~/Music/tide.lrc
# 只有歌词：npm run song -- --lyrics tide.txt --dry-run 先看时间轴
```

- `--audio` 用 ffmpeg 转成 `assets/music.wav`（48kHz 立体声，encode 自动混入并按片长循环/裁剪）。
- `.lrc` 用 `[mm:ss.xx]` 时间码；`.txt` 按行均分在片头留白到片尾之间。工具会重写 `js/script.js` 并打印语速/长度告警。
- **歌词只解决“唱到哪一句”，不解决“画面讲什么”**：拿到歌词后仍要重排 `film.js`，让每句歌词落在一个有动作的镜头上。
- 歌词定稿后再做配乐/混音；改歌词后重跑 `npm run song`，不要手改两处。

## 7. 分辨率与交付

- 原生画布 **1920×1080**：场景坐标、纸层尺寸、字形全部按它写；1080p 是默认交付。
- 4K 不是“放大”：`renderScale: 2` / `render.js --scale 2` 把画布后备改成 3840×2160，矢量按 2 倍设备像素重画。画布 CSS 尺寸与场景坐标都不变。
- 先在 1080p 审片；只有用户明确要 4K 才渲 4K，渲前先看磁盘（doctor 会估）。
- 记住 `?scale=` 只在渲染/QA 时覆盖设备像素比；不要在场景里读 `window.devicePixelRatio` 做布局。

## 8. 确定性（硬规则）

- 引擎只依赖 `local` 时间与 `shot.v`；禁止 `Math.random()` / `Date.now()`，随机走 `K.rnd(seed)`。
- 同一时刻两次渲染必须逐像素一致（`qa-mv` 会比对，容差 ≤2 色阶）。
- 云的漂移、雨丝、纸纹、浪花全部由帧时间驱动；暂停在任意时刻都应是一张完整构图。

## 9. QA 判据

`node tools/qa-mv.js .` 逐镜 45% 时刻检查：

- 画布后备 = 1920×scale × 1080×scale（scale 1 = 1080p，2 = 4K）；
- `window.FILM_GENRE === 'paper-story'`，且没有宣传片层（`FILM_LOOK`）；
- 每镜 ≥24 种颜色、≥12% 有内容（防空白/全黑）；
- 同刻两次渲染最大差 ≤2 色阶；
- 镜头内 +0.45s 必须有变化（防静帧）；
- 每条歌词中点，画布歌词文字与剧本一致且 alpha ≥ 0.5；
- 最后 1.2s 已停在 `end` 片尾卡上。

`tools/qa-all.js` 再按每镜 30% / 78% / 切点前 0.25s 抽帧。**78% 是最容易出问题的一帧**：动作是否收住、纸层是否只剩残影、歌词是否压住主体。抽帧必须逐张看，不能只看报告。

## 10. 常见坏帧与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 楼群底下漏海 / 楼与楼之间漏海 | 城镇没有连续地基，前后排楼底不齐 | `K.town` 先画一条连续岸线（高度 = tail + 后排下压量），再画楼 |
| 浪的右缘是一条竖直墙 | 浪的收尾直接 `lineTo(x, H)` | 用两段 bezier 把浪尾收进画面底边，左右两列浪错开 |
| 浪花浮在半空 / 排成一条水平线 | 浪花按固定 y 采样，没跟浪脊 | 沿实际 crest 路径采样，加少量抬升与相位抖动 |
| 窗雾像肥皂泡网格 | 用规则圆点铺满 | `K.fogOnGlass`：整面 evenodd 薄膜 + 径向羽化擦痕 + 小簇霜花 |
| 擦窗的手印是一圈亮环 | 画了完整圆弧 | 只留一段低 alpha 的宽擦痕 + 一条细反光，不闭合 |
| 脸上有划痕状亮线 | 轮廓光沿错误轮廓画了长弧 | 轮廓光只贴在头发/肩线外侧，短、分段、低 alpha |
| 泪是一条白色小棍 | 泪滴画成了长条 | 一颗小水滴（圆 + 短尾），高光只点一下 |
| 人物像贴纸浮在纸上 | 没有投影/纸边 | 人物也用 `K.paper`，投影方向与场景一致（右下） |
| 同刻两次不一致 | 用了未播种随机/时钟 | 改 `K.rnd(seed)`，时间只从 `local` 来 |
| 镜头内没变化 | 场景没有任何 live 层 | 加浪/雨/火光/雾/船晃/呼吸，或换一个有动作的镜头 |

## 11. 加新场景 / 新角色

- 场景在 `js/paper-sets.js` 注册 `S.<name> = function (g, shot, local, slot) {…}`，用 `K.pal(shot.mood)` 取色、`K.rnd(shot.v * … + seed)` 派生微差。
- 新场景必须能画出 `wide / mid / close` 三种景别中至少一种，并且每帧有至少一层在动。
- 新角色先加进 `paper-figures.js`（剪影、背面、手的画法分开），再在 `film.js` 里用 `who` 引用；不要把人物画进场景函数。
- 新纸层必须走 `K.paper`；新光源必须走 `K.glow`/径向渐变，不要用纯白硬边。

## 12. 交付前检查单

1. `npm test` 全绿（分镜连续性、2–3 秒、唯一 v、歌词、确定性、图层隔离）。
2. `npm run qa` 全绿，`qa/mv/` 抽帧逐张看过，重点 78% 与切点前 0.25s。
3. 封面帧能独立当缩略图（片名完整、无动画中间态）。
4. 1080p 审片通过后再按需渲 4K。
5. `encode.js` 输出后核对时长/分辨率/帧率/音轨；无声版是合法交付，不要为了“有声音”硬塞音乐。
6. 交付只留成片与封面；删掉 `frames/`、`stills/`、`qa/` 等中间产物前先确认。

## 13. 3D 纸剧场（可选引擎 `engine: "cg"`）

同一个故事、同一张 24 镜表，改用 Blender EEVEE 渲染成**有厚度的纸剧场**：纸片有真实厚度与纸芯白边，海有前后层与景深，灯是真的灯（面积光、点光、体积雾），镜头是真的相机（焦距、光圈、手持微漂）。它仍然是剪纸——没有写实材质、没有贴图、没有 AI 生图，画面全部由 Python 几何与程序化纸浆纹生成。

**什么时候用**：用户要“更立体 / 更有光影 / 像定格动画布景”的 MV，或默认 Canvas 引擎的平面感已经撑不住故事的近景。默认仍是 `engine: "paper"`（Canvas 2D）；3D 是逐支片的升级选项，不自动启用。

### 13.1 文件与管线

| 文件 | 作用 |
|---|---|
| `cg/paper.py` | 纸片几何库：`cut()` 挤出面片、`figure()`/`bust()` 纸人、`boat`/`lighthouse`/`lamp_lantern`、雨/雾/光束/关键帧工具 |
| `cg/mv3d.py` | 24 镜表与全部搭景函数；底部 `SHOTS` 列表驱动 `FILM.run()` |
| `cg/cg_film.py` `cg/cg_kit.py` `cg/cg_vfx.py` | 导演模块（逐帧搭景、全局帧、续渲）、灯光/材质/相机、粒子与体积 |
| `tools/cg-render.js` | 帧渲染 CLI；`--at` 出静帧到 `stills/`，`--from/--to` 按秒分段，`--resume` 续渲 |

```bash
npm run subs                                  # 歌词 → assets/subs.ass（ASS 烧字）
node tools/cg-render.js --at 6.2,23.7,38.7    # 低采样抽帧 QC，先别看全片
node tools/cg-render.js --from 0  --to 30 &   # 分两半并行，墙钟时间减半
node tools/cg-render.js --from 30 --to 60 &
node encode.js --subs assets/subs.ass         # 音乐 + 烧字 → out/final.mp4
node tools/repair.js .
```

分镜仍是 2.5s/镜 = 75 帧 @30fps；`SHOTS` 的每一项是 `('s18', s18, '一句话说明', bake, exposure)`，曝光逐镜给——风暴 0.15、夜 0.25、黎明 0.45，不要全片一个值。静帧时间 T 属于第 `floor(T/2.5)+1` 镜；文件名不补零（`still_6.20.png`）。

### 13.2 纸剧场画法（都是踩过的坑）

- **要合并成一个轮廓的部件必须 `edge=None`**：`cut()` 的 `edge` 会沿整块多边形描一圈奶油纸边，发髻、头、手臂和身体之间就会出现“贴上去的接缝”。发髻、头盘、臂带一律不描边。
- **胸像就是侧脸**：鼻子/嘴唇/下巴相对面部前缘只允许 0.02–0.03（h 归一单位）的起伏。鼻子突起 0.04 以上会变成鸟喙，下巴拉长会变成胡子。改完必须出一张 80mm 特写核对。
- **近景五官不靠几何靠光**：把一颗小自发光圆片（`disc` + `glow_mat`）贴在脸颊平面上做眼神光；泪滴是**完整落在黑色脸颊内部**的小胶囊，碰到轮廓边缘就会被亮天空同化、读成脸上一个洞。
- **暖光不能从正面打**：正面补光会把黑纸打成褐色团块。火光、炉光、灯光的 kicker 放在身后低处（y 在纸片后方、z 低于脸），只染轮廓边缘；脸保持剪影黑。
- **躺/睡的姿势要单独搭**：把站姿纸人旋转 82° 会得到一块带断头的木板，`sleep` 姿态缩到近景会读成一只鸟。直接写坐姿/蜷姿的多边形，头用小半径（≈0.05h）枕在膝上，手臂不要。
- **景别用数学定，不靠试**：`cam()` 的半画幅 = dist·18/lens。先算“头宽要占画幅多少”，再反解距离与焦距；感觉不对时先改机位，不要改 lens 硬拉。
- **每一层都要有值差**：贴着天空的细节（窗、雾片、剪影边）如果和天空亮度接近，就会读成破洞。加雾片前先问“它在天空前还是天空后”。

### 13.3 成本与排错

- M 系列单进程约 4.3 s/帧 → 1800 帧 ≈ 2.1 小时；两半并行约 75 分钟。**开渲前先抽 6–8 张静帧逐张看**，坏一帧等于重渲半支片。
- `--resume` 只补缺帧；改了 `cg/*.py` 就会影响之后每一帧，别在渲染中途改脚本——要改就停、改、从断点续。
- 渲染进程被杀后，先数 `frames/` 帧数与最大帧号，再决定从哪个秒续。
- `node encode.js` 不带 `--subs` 就没有底部歌词；3D 版的歌词是 ASS 烧进画面的，不再由画布绘制。
