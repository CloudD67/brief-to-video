# 产品片语法 · 真屏

> 来源：CrewVela 开源宣传片（抖音，1920×1080 / 30fps / 61.27s）逐帧实测。
> 它值得学的是**怎么让软件产品片看起来像有人真的在用产品**；
> 它的配色、吉祥物、字标、CTA 是**它自己的品牌皮肤**，与本仓库无关。

适用：SaaS、AI 工具、开发者平台、Agent / 工作台、App 发布。
不适用：餐饮、城市、实体产品、生活方式——那些走编辑/影像语法，别硬套。**硬件/实体产品（笔记本、耳机、相机、汽车……）不适用本文，改写 `hardware-promo-grammar.md`：产品必须在真实空间与光里，屏幕镜头 ≤30%。**

---

## 0. 第一条规矩：只学技术，不学皮肤

拆参考片时把每一帧拆成三层，只有前两层能进模板：

| 层 | 内容 | 处理 |
|---|---|---|
| **技术层** | 全出血界面、长镜 + 子节拍、拍点量化、硬切、间幕卡时序、字幕时序、真实卡片与真实数据 | 学，写进文档与 kit |
| **零件层** | 窗口/分栏/终端/看板/卡片/弹窗/任务条/对话记录/拼贴/连线 | 复用，做成 `screen-kit.js` |
| **个性层** | 配色、胶囊颜色、吉祥物、双色字标、三胶囊 CTA、口号、具体镜序与文案 | **不学**，每支片按当次 brief 重新长 |

判断有没有抄错层：把片名、品牌名、产品名换掉，如果画面还能原样成立，
说明你把别人的**个性**当成了模板。正确的结果是：技术一样，画面完全不同。

皮肤的唯一来源：当次的 brief / 品牌 / 主题（`--accent`、`--paper`、`--ink`、字体）。
组件里任何写死的颜色都算 bug，`npm run check` 会拦。

## 2. 技术层：九条语法

### 2.1 一条任务贯穿全片

全片只做一件事：提出任务 → 执行 → 卡住 → 换人接手 → 组队 → 交付。
产品能力不是"讲"出来的，是这条任务推进时**被迫展示**出来的。

> 写分镜前先写一句：**"谁，要完成什么任务，卡在哪，谁接手。"**
> 这句话写不出来，就不要开渲。

### 2.2 全出血屏幕，不做画中画

界面铺满画布，边缘的面板**故意被画框切掉一半**（左栏露出半截、右栏出画）。
这是"真实屏幕"的最强信号：真实工作区永远比窗口大。
反例：把 UI 缩成一张圆角卡片放在版心里，旁边留白写标题——那是发布会 PPT。

### 2.3 长镜头 + 子节拍

一个屏幕镜头 8–16s，内部至少 4–6 个子节拍：
输入 → 运行 → 出结果 → 传手 → 新状态。
**任何 1.5s 内必须有东西在变**：光标闪、行在长、状态点变色、连线在走、列表在进。
只有间幕卡允许"静"——它靠自己的 1.9s 动画撑住。

### 2.4 切点落在音乐栅格上

所有镜头长度量化到 1.93s（4 拍）。间幕卡正好一拍。
先定 BPM（120–128），再按拍数写镜头表，最后才写画面。
"流畅"不是靠运镜，是靠**画面和音乐共用一张网格**。

### 2.5 间幕卡是唯一的平面设计

全片只有间幕卡和结尾卡是"设计过的平面"：纯底色、纯文字、
一个强调色短语、一条下划线。没有插画、没有装饰线、没有编号。
**频次：3–4 次，每次一句话。** 它负责把长屏幕切成章节，不负责解释产品。
底色与文字色一律用 `var(--paper)/var(--ink)/var(--accent)`，跟着主题走。

### 2.6 两种字幕，一条一拍

- **章节式**：短胶囊（2–4 字，`var(--scr-accent)`）+ 54px 大字
- **陈述式**：只有 54px 大字

字幕在画面底部、居中、只出现一条，入场 0.26s、退场 0.16s。
全片 3–4 条。**不要每 2 秒一条旁白式字幕。**

### 2.7 真实卡片要有"种类"，不是一种卡复制八遍

参考片里的可信度来自**不同拓扑的卡片同时存在**：
终端（行在长）、看板（标签页 + 筛选 + 计数）、角色卡（头像 + 角色标签 + 描述）、
交接弹窗（谁交给谁 + 原因 + 确认按钮）、任务条（状态 + 时间 + 编号）、
对话记录（两方气泡 + 时间）。每种只在自己的镜头里当主角。
用 `screen.term/board/card/dialog/taskbar/chat` 拼，不要用一张万能卡改字。

### 2.8 界面文字必须小

真实界面的正文是 20–28px，卡片名 25px，终端 23px。
把 UI 文字放大到 40–60px 会立刻变成"信息图"。
**想强调什么，用字幕和间幕卡，不要放大 UI。**

### 2.9 一个主色 + 一个意外色，不做彩虹

中性灰阶打底，主色 = 主题 `--accent`，再留一个面积 < 3% 的意外色
（成功态/警告态/一个图标）。色彩单一的反面不是彩虹，是**有层次的中性底**。
参考片用什么颜色与这支片无关——它的奶油底、紫、橙吉祥物都是它的个性。

## 3. 转场技术（只这三种）

| 转场 | 做法 | 代码 |
|---|---|---|
| **硬切** | 无淡入淡出、无闪白、无全片漂移；上一镜最后一帧直接换下一镜 | `motion: 'locked'` |
| **间幕卡进出** | 硬切进纯色面 → 卡内 fade-only + 下划线画线 → 硬切走 | `screen.intertitle()` |
| **蒙太奇快切** | 1 拍内切 1–2 个界面细节（聊天/任务条/日志），每刀 1.93s | 两个 0.97s 场景或一个场景内硬换内容 |

不要：溶解、缩放转场、白闪、飞入、旋转 3D。真屏片的"贵"来自克制。

## 4. 一镜之内：10 秒的子节拍

```
0.0–1.0  建立：三栏工作区已就位，光标在闪（硬切进来，不做入场动画）
1.0–3.2  输入：任务被逐字敲进终端
3.2–4.6  运行：日志逐行出现，状态点变色
4.6–6.4  结果：✓ 12 tests passed，计数落值
6.4–8.2  传手：连线亮起，焦点移到右栏，另一个 Agent 接手
8.2–10.0 收束：新任务出现在队列，画面停在"正在进行"
```

写法：每个子节拍一个 `inv(local, at, dur)`，全部挂在同一个 `seek` 里。
不要为每个子节拍切一刀——**切点越少，界面越真**。

## 5. 间幕卡配方（时序实测）

| 时间 | 发生什么 |
|---|---|
| 0.00 | 硬切到纯色面（无淡入、无位移） |
| 0.10–0.52 | 第一句从 0 淡入到 1（纯透明度，不移动） |
| 0.50–0.92 | 第二句（强调色）淡入 |
| 0.80–1.22 | 下划线从左到右画出（scaleX 0→1） |
| 1.22–1.93 | 静置，然后硬切走 |

- 画布 `var(--paper)`；正文 `var(--ink)`；强调 `var(--accent)`
- 字号 104px、字重 700、整句水平居中、单行
- 下划线 4px，距基线约 0.2em，只画在强调短语下面
- **没有位移、没有缩放**——静止就是标点

对应实现：`screen.intertitle([{text:'前半句'},{text:'强调短语',accent:true,underline:true}])`。

## 6. 字幕配方（时序实测）

```css
胶囊 var(--scr-accent) 底 / var(--scr-accent-ink) 字 / 34px / 圆角 9px / 内边距 9×18
大字 54px / 700 / var(--scr-text) / 字距 0.01em / 行高 1.1
间距 18px，整体距底 62px，水平居中
```

- 入场：胶囊 0.26s 弹入（scale 0.92→1），大字晚 0.08s、上移 12px 淡入
- 退场：0.16s 整体淡出（不要滑走）
- 一条字幕只挂一个镜头，不跨切点

对应实现：`screen.caption('章节名', '一句话说明')`。
字幕是画面内的二次信息，与 `js/script.js` 的烧录字幕不重复。

## 7. 真实度清单（抽帧对照，逐条打勾）

- [ ] 界面里有**真实文件名/路径**（`src/middleware/rate-limit.ts`），不是"模块 A"
- [ ] 有测试数量与耗时（`✓ 12 tests passed`、`built in 2.41s`）
- [ ] 有状态点（运行中 / 已完成）且颜色会变
- [ ] 至少出现一次**错误 + 修复**（`! 窗口重置没有处理时钟回调` → `✓ 已回复`）
- [ ] 光标在闪（1.8Hz，不是常亮）
- [ ] 每个面板都有 1px 分割线，没有大块纯色空面
- [ ] 至少一个面板**被画框切掉半截**
- [ ] 有 tab 数字徽标、筛选胶囊计数
- [ ] 有等宽字体区域（终端 / 仓库名 / 快捷键）
- [ ] 卡片种类 ≥ 3（终端 / 看板 / 弹窗 / 任务条 / 对话任选）
- [ ] UI 正文 20–28px，没有为了"看得清"而放大
- [ ] 图标像产品图标（字母块），不是通用几何图形
- [ ] 每一秒都有东西在动（抽 3 帧对比，静帧率 0）
- [ ] 没有插画、没有纸纹、没有装饰编号压在界面上
- [ ] 字幕 ≤ 4 条，间幕卡 ≤ 4 张
- [ ] 出画面板给文字留了内边距：切掉的是面板边缘，不是半个字/半个标题
- [ ] 标题栏不换行、不挤压：窄窗口别硬塞状态文字
- [ ] 每个面板都有 2–3 行真实内容：空壳窗口比动画更假
- [ ] 弹窗压暗是压深（浅色皮肤也是），不是盖一层白雾

## 8. 用本仓库怎么拍

### 8.1 有真实产品页

```bash
npm run capture -- --url https://your.app --scene s2 --seconds 9 --fps 2 \
  --scroll 0:600 --cursor 900:420 --click 1180:210
npm run media      # 抽帧 → js/media.generated.js
```

只抓自有或已授权的页面；登录墙、付费墙、竞品后台不要绕。
抓帧后用 `kit.frame` 播放，画面里保留真实字体与真实数据。
**能抓到真页面，就不要手画 UI。**

### 8.2 没有可抓页面（Beta / 内部工具）

用 `js/screen-kit.js` 手搭一块**发布级**界面：
`stage()` → `win()` × N → `term()` / `board()` / `card()` / `dialog()` / `taskbar()` / `chat()` → `caption()`。
所有文字写进 `js/script.js` 的场景节点，不写死在场景里。
浅色产品加 `stage({ light: true })`，只换灰阶，不换结构。

### 8.3 关键配置

```js
// js/config.js
look: 'tech-editorial',   // 气质参考；画面本身会盖住主题底
motion: 'locked',         // 关掉全片漂移与切点闪白（真屏片必须）
```

### 8.4 场景骨架

```js
S.push({
  id: 's2', start: 15.8, end: 27.4,
  mount(root) {
    const st = screen.stage(); root.appendChild(st);
    const a = screen.win({ x: -60, y: 0, w: 980, h: 1080, title: '代码审查', icon: screen.icon('C','accent') });
    const t = screen.term(); a.body.appendChild(t);
    const d = screen.dim(); st.appendChild(d);
    const box = screen.dialog({ x: 640, y: 320, title: '交接给 @reviewer', rows: [['原因', '上下文窗口不足']] });
    st.appendChild(box);
    this.n = { st, a, t, d, box };
  },
  seek(local) {
    const t = this.n.t.lines;
    screen.type(t[0], '给 /login 加上限流', screen.inv(local, 0.8, 2.2));
    screen.reveal(t.slice(1), local, 3.2, 0.10, 0.3);
    this.n.d.seek(local, 6.4);
    this.n.box.seek(local, 6.5);
  }
});
```

### 8.5 零件速查

| 需要什么 | 用哪个 | 真实感要点 |
|---|---|---|
| 应用外壳 | `win({title,sub,status,tone})` | 标题栏有状态点，按钮 3 个 |
| 三栏工作区 | `split()/col()/divider()` | 至少一栏出画 |
| 执行过程 | `term()` + `type()/reveal()/caret()` | 真命令、真路径、真耗时 |
| 任务看板 | `board({tabs,filters,field,note,cols})` | 徽标有数字，筛选有计数 |
| 实体卡片 | `card({avatar,name,tags,desc,left,right})` | 一句话描述 + 页脚元信息 |
| 交接/确认 | `dialog({title,sub,rows,actions})` + `dim()` | 有一个"原因"行 |
| 进行中的任务 | `taskbar({title,meta,status})` | 编号 + 时间 + 状态 |
| 对话 | `chat([{who,text,me}])` | 两方气泡，按节奏逐条进 |
| 章节标点 | `intertitle()` | 只用纸/墨/主色 |
| 结尾 | `collage()` + 自建字标块 | 拼贴是结构，排版按本片品牌 |

### 8.6 QA 契约（真屏片和普通版式的判定不一样）

- 出画是设计不是错误：`win/term/board/card/dialog/taskbar/chat` 自动带 `data-bleed`，
  `qa:layout` 跳过它们的出画/裁切判定；字幕、间幕卡、普通版式文字仍按画框判。
- 窗口按钮（− □ ×）带 `data-decor`，`qa:timing` 不把它们当占位符。
- 真屏片的字幕轨可以空着（信息在画面内的 `screen.caption`）；单测只对含 `screen-kit` 的工程放行。
- 间幕卡是独立场景时没有 `.scr-stage`，编辑版式的分栏刻线/竖排标签/页眉页脚一律不渲染；
  场景里一旦出现 `.scr-stage` 或 `.scr-inter`，这些编辑装饰自动关掉。
- 渲染模式自动隐藏预览进度条（`html[data-render="1"]`）。

## 10. 个性示例（参考片这么做，**不要照抄**）

以下仅用于理解"技术如何被包在皮肤里"，任何一项都不属于本模板：

- 奶油纸底 + 暗紫文字 + 近黑界面；淡紫胶囊字幕
- 橙色像素吉祥物，只出现在边角
- 结尾双色字标（前半黑、后半紫）+ 橙色短线 + 三颗胶囊 CTA
- 固定的镜序：任务 → 审查 → 卡住 → 交接 → 组队 → 看板 → 细节 → 拼贴

正确用法：抽掉这些，只留"中性底 + 一个主色 + 一个意外色""拼贴 + 字标 + 一句口号"的**结构**，
再用当次品牌重新填。填完做换名测试：换成另一个同类产品，画面应当不成立。

## 11. 反模式（逐条对照）

| 反模式 | 为什么假 | 改成 |
|---|---|---|
| 抽象纸片、蓝线、漂浮隐喻 | 观众看不到"产品在干什么" | 全出血界面 |
| 七个场景共用一套页眉页脚 | 一眼模板 | 每镜一套真实版面，边缘出画 |
| 单一蓝色从头到尾 | 单调 | 中性灰阶 + 主题主色 + 一个意外色 |
| 4–6s 一切，切完静止 | 不流畅、不真实 | 8–16s 长镜 + 子节拍 |
| 大字报 + 插画解释功能 | 像海报不像产品 | 任务驱动，界面自己说话 |
| 每 2 秒一条字幕 | 像旁白 PPT | 全片 3–4 条，一条一拍 |
| 居中卡片 + 留白 | 发布会 PPT | 满屏窗口，切掉一半 |
| 把参考片的颜色/胶囊/字标搬过来 | 换了个片名，还是同一支片 | 皮肤按当次品牌重定 |

## 12. 验收（渲完必看）

1. 0.5s 处暂停：能不能看出这是**某个真实软件**？看不出就重画。
2. 每 1.93s 抽样一帧：有没有连续两帧几乎一样？有就补动作。
3. 遮住字幕：故事还讲得通吗？讲不通说明画面没干活。
4. 遮住间幕卡：节奏还成立吗？成立说明间幕卡没白放。
5. 把片子静音看一遍：切点是否仍落在呼吸上？
6. 换名测试：把品牌换成另一家，画面还成立吗？成立说明又在抄皮肤。
7. 跑 `npm run qa:motion` 与 `npm run qa:variety`，再跑 `npm run repair`：运动与色彩不达标、或 repair 报错，都不算完成。修法见 `repair-loop.md`。
